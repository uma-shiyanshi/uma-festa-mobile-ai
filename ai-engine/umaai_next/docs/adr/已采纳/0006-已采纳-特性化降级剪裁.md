# ADR-0006: 特性化降级剪裁

- **状态**：已采纳
- **日期**：2026-10-17
- **关联**：`crates/umasim/Cargo.toml`、`crates/umaai/Cargo.toml`、`crates/umaai-update/Cargo.toml`、`.github/workflows/ci.yml`

## 背景（Context）

下游宿主（如 Web WASM、Android、嵌入式 DLL）通常自行喂入帧数据且受限于多线程或文件系统环境。若 `rayon` 并行库、文件监听库（`notify`）或 HTTP 客户端被强制编入核心依赖链，会导致下游无法构建或包体积膨胀；同时若仅在入口包传 `--no-default-features`，workspace 内部依赖边仍会重新开启默认特性。

## 决策（Decision）

1. **稳定面按能力特性化**：
   - `umasim` 将并行计算收口为 `parallel = ["dep:rayon"]`（默认开启），关闭时 `search/par.rs` 逐字退化为串行收集，结果逐位一致；
   - `umaai` 以 `default-features = false` 引入 `umasim` 并同名透传 `parallel`，同时将文件通道与目录监听收口为 `file-channel` 特性（按传输类别命名）；
   - `umaai-update` 独立于引擎链，通过 `http` 特性剪裁网络传输依赖。
2. **降级与守门边界**：仅对**引擎稳定面**（`umasim` / `umaai` / `umaai-update`）承诺 `default-features = false` 降级可用，主线样例面（`umaai-cli` / `umaai-tools` / `umaai-tests`）不作承诺；CI 增设无默认特性编译与串行引擎测试，并校验依赖图不含被剪裁的依赖。

## 影响（Consequences）

- **收益**：下游宿主只需声明 `default-features = false` 即可获得无线程、无文件监听的纯内存引擎形态，且串行/并行计算结果逐位一致。
- **约束**：在 `umasim` / `umaai` 中引入平台相关或重型依赖时，必须同步评估是否受 `parallel` / `file-channel` 特性门控，并通过 CI 降级档验证。
