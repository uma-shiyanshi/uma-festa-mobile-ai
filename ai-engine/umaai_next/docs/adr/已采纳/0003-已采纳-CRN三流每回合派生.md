# ADR-0003: CRN 三流每回合派生

- **状态**：已采纳
- **日期**：2026-10-17
- **关联**：`crates/umaai-core/src/rng.rs`、`crates/umasim/src/game/{traits.rs, base/mod.rs, base/basic.rs}`、`crates/umasim/src/search/`

## 背景（Context）

早先随机流仅在单条流或局部剧本中分流，搜索对比需要依赖外挂的「按阶段重播种（`crn_stage_reseed`）」机制来对齐随机输入；同时若决策抽签与规则随机共用同一流，策略选择会干扰后续局面随机性，破坏共同随机数（CRN）配对。

## 决策（Decision）

1. **三条规则流 + 独立决策流**：
   - `TurnFixedRng`（回合固定流：人头分布、Hint、回合固定事件）与 `EventRng`（事件流：回合开始事件链）由 `BaseGame` 持有；
   - `StrategyRng`（策略流：训练成败、比赛、休息/外出等机制随机）由具体 `Game` 自持；
   - 决策流作为 `run_stage(trainer, rng)` 参数**只喂给 `Trainer`**，整局连续不重置。
2. **每回合从 `rule_master` 重新派生**：进入新回合时按 `(master, turn, tag)` 重新派生各规则流（counter 归零），使同回合规则随机与策略/决策流消耗无关；删除外挂「按阶段重播种」接口与配置键。
3. **强制注入与 `Deref` 防重名**：`set_rule_master` 为唯一主种子注入点，未注入直接报错；`BaseGame` 底座入口命名为 `init_rule_streams`，禁止与契约 `set_rule_master` 同名，防止 `Deref` 静默解析。
4. **`fork_for_rollout` 唯一分支入口**：搜索分支必须经此方法克隆并注入 rollout 种子及重置自持策略流。

## 影响（Consequences）

- **收益**：CRN 配对由规则层天然保证，同一主种子下同回合规则随机完全一致，支持无外挂重播种的分支对比。
- **约束**：新增任何不由传入 `rng` 驱动的剧本随机流，必须在 `set_rule_master`、回合边界与 `fork_for_rollout` 三处同步重置，否则可复现性静默失效。
