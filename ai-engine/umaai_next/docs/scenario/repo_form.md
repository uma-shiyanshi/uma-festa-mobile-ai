# 剧本仓边界与引擎钩子流程

> 适用范围：引擎维护者在评审跨仓需求、模板边界与引擎钩子时遵循的规范。
> 剧本仓内部结构（五 crate 分工、数据配置、文档体系、测试与验收）以 [`templates/umaai-scenario/`](../../templates/umaai-scenario/README.md) 为准，本文不再重复。

## 1. 模板与跨仓边界

- **独立仓**：剧本仓以依赖引用 `umaai-core` / `umasim` / `umaai`（开发期 `path`、稳定期 git `tag`、下游宿主 `default-features = false`）。
- **模板边界**：[`templates/umaai-scenario/`](../../templates/umaai-scenario/README.md) 只固化与剧本无关的接线（workspace 布局、数据与配置载入、阶段投影、规则流接线、测试定位、手动训练员）；阶段、事件、训练、比赛、资源账本等强依赖剧本的形态不预置实现。
- **零修改接入**：接入新剧本时引擎仓 `git diff` 为空；剧本仓不 fork、不复制引擎私有逻辑。

## 2. 引擎钩子流程

缺通用能力时回引擎仓加钩子，按以下纪律执行：

| 项 | 规则 |
|---|---|
| 准入判据 | **跨剧本复用**且**与具体剧本、具体算法无关**（「零依赖」只是必要条件） |
| 形态 | **带默认实现、非破坏**；默认实现即旧行为，剧本按需覆写或调用 |
| 申请内容 | 痛点（现在要复制哪些逻辑）、期望形态（签名 / 语义）、默认行为、影响面（是否动基线） |
| 等价性声明 | 提交说明点明**默认行为是否等价**；不等价需重录引擎 L4 基线，并通知下游剧本仓在 `changelog.md` 记口径 |
| 命名纪律 | `Deref` 底座的方法不得与契约方法同名（基座入口 `init_rule_streams` vs 契约 `set_rule_master`） |
| 复用优先 | 已落地的通用件直接调用，不另写一份（比赛事件构造、训练后默认处理、羁绊出口、红点口径、分桶采样、配置覆盖层 helper） |
| 禁止 | 在剧本仓改引擎源码、把引擎内部类型复制进剧本仓、绕过默认档自建第二套随机对齐 |
