## 2. S0 阻塞闸门与协作口径

| 状态 | 含义 | 是否阻塞 | 处理规则 |
|---|---|---|---|
| **机制未确认** | 规则逻辑、触发条件、结算顺序、交互形态未知或存在多解 | **阻塞** | 禁止「先写一版」；牵动阶段机 / 动作集 / 资源系统时整仓暂停，按 [`intake.md`](intake.md) 分组向用户核对至清零 |
| **数值待确认** | 机制已确认，具体数值 / 概率 / 上限 / 表项未到 | **不阻塞** | 集中存放在资产 / 配置 / 常量表并标记 `STUB` / `TBD`，同步登记 [`stubs.md`](stubs.md)；替换后重录基线并记入 [`changelog.md`](changelog.md) |
| **已确认** | 机制与数值均已确认 | — | 标注来源与确认日期，落盘对应文档 |

> **S0 通过条件**：[`intake.md`](intake.md) 中无「机制未确认」项，且已向用户逐节走查确认关键机制与术语，方可进入 S1。

## 3. 标准阶段路线（S0–S9）

每步以「可交付 + 四档测试全绿」收尾，不跨阶段堆改动。

| 步 | 内容 | 产出 / 落点 | 验收 | 状态 |
|---|---|---|---|---|
| **S0 机制与用语核对** | 收集来源、核对静态表、逐组向用户确认机制与术语 | [`intake.md`](intake.md) + [`mechanism.md`](mechanism.md) + [`../GLOSSARY.md`](../GLOSSARY.md) | 无「机制未确认」项，用户确认开工 | ☐ |
| **S1 建仓与装配** | 改名、调整依赖三档、拷入 `data/`、改 CI | 可编译空壳 + 可启动 bin | `fmt` / `check` / `clippy` / `test` 绿 | ☐ |
| **S2 数据层** | 剧本资产 schema（严格校验）+ 剧本配置覆盖层 | `core/src/data.rs`、`config.rs` | 载入 / 缺字段 / 未知键 / 长度一致性单测 | ☐ |
| **S3 局面与阶段机** | `Game` 2 关联类型 + 22 必备方法、阶段枚举与 `StageId`、三轴随机、`fork_for_rollout` | `core/src/game/{mod,stage}.rs` | 固定种子跑满回合、两次逐位一致、未注入主种子报错 | ☐ |
| **S4 动作与结算** | `ActionEnum` + `apply`、训练 / 比赛 / 休息 / 出行 / 治病等动作集 | `core/src/game/action.rs` | 单动作单测；`apply_root_action` 与 `run_stage` 逐字一致 | ☐ |
| **S5 机制** | 剧本资源、训练加成、特例公式、上限与分档 | `core/src/game/*`、[`mechanism.md`](mechanism.md) | 每条数值口径一个机制单测（公式 + 边界） | ☐ |
| **S6 事件** | 固定回合 / 角色 / 随机分布事件生成与特例结算 | `core/src/game/event.rs`（按需新建） | 固定回合、分布抽样、成功/失败分支单测 | ☐ |
| **S7 训练员** | 手写守门链 + 打分表 + 事件选项 | `core/src/trainer.rs` | 覆盖全部决策点、无死循环 | ☐ |
| **S8 装配与呈现** | `build_game`、配置接线、View 快照、`cli` 入口与选择器 | `core/src/game/mod.rs` + `cli` | 一局端到端、View 序列化、未知选择器报错 | ☐ |
| **S9 基线与验收** | 固定种子基线、更新 [`tests_overview.md`](tests_overview.md) 与状态 | `baselines/` + `docs/` | 基线自动判定、文档链接可解析、四档全绿 | ☐ |

## 5. 扩展轨与优化轨（按需启用）

### 5.1 MCTS 扩展轨（M0–M4，S7 后按需）

| 步 | 内容 | 验收 |
|---|---|---|
| **M0** | 实现 `FlatSearchGame`：`SUPPORTS_TRUNCATED_LEAF = false`、`apply_root_action` 与 `run_stage` 一致、`fork_for_rollout` 克隆并重置自持流 | 同 `master` 两次搜索逐位一致 |
| **M1** | 实现 `MctsTrainer`：动作决策走 `FlatSearch`，事件选项走手写，不可用时回落手写 | 全部决策点有落手，搜索/手写可切换 |
| **M2** | 搜索参数进剧本配置段（未知键报错，不读引擎默认冒充剧本默认） | 默认层可解析、覆盖层生效 |
| **M3** | 固定根对照、CRN 配对、跨种子复现、`SearchProbe` 观测 | 两次运行逐位一致 |
| **M4** | 锁定搜索档独立基线（与手写档分开，不可混比）并更新文档 | 基线自动判定通过 |

### 5.2 NN 特征轨（N0–N5，仅特征定义与提取）

| 步 | 内容 | 验收 |
|---|---|---|
| **N0** | 冻结局面状态、候选动作、终局目标三类特征的字段、顺序与归一化 | 每个维度有来源字段与口径说明 |
| **N1** | 剧本侧 `features` 模块：只读纯函数 `encode_state`，定义 `INPUT_DIM` / `FEATURE_VERSION` | 同局面两次编码逐位一致 |
| **N2** | 维度 / 范围 / 确定性单测 + golden 快照守门（改序/改宽必 bump 版本） | 守门测试全绿 |
| **N3** | 导出特征 + 动作索引 + 搜索分数/终局记录为离线数据集 | 只导出不训练，样本可复现 |
| **N4** | 引擎估值接缝（延后；未接入前 `SUPPORTS_TRUNCATED_LEAF` 保持 `false`） | — |
| **N5** | 明确不做：数据集规模化、训练、ONNX 推理、leaf 截断（另立方案） | — |

### 5.3 性能优化轨（O0–O4，S9 后按需）

| 步 | 内容 | 验收 |
|---|---|---|
| **O0** | 固定构建 / 数据 / 配置 / 种子 / 线程锁定基线 | 同参数两次运行逐位一致 |
| **O1** | 先 microbench 拿分段绝对成本，再整局 A/B 定端到端方向 | 热点以专用测试数据为准 |
| **O2** | 每次只改一个点，保持 RNG 调用、遍历与浮点运算顺序 | A/B 非耗时输出逐位一致 |
| **O3** | 针对性 Release 测试 + 全量测试 + 固定根 + 整局对照 | 四档全绿，收益与范围写明 |
| **O4** | 保留探针 / 微基准入口与命令，清理临时产物（产物不入仓） | 命令可复跑 |
